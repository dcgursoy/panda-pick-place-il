# Milestone 2: dataset core

Date: 2026-10-31 (overnight run). Same machine as before, driver 32.0.101.9150.

## What was built

- `panda_il/data/schema.py`: the dataset directory layout (`metadata.json`, `episodes.zarr/`), schema version 1, `Dataset` (create / open / write / read episodes, counts), `DatasetMetadata` (env version and config, rates, camera intrinsics and clock settings, action and observation specs, stream specs, MuJoCo state spec and size, library versions, git commit and dirty flag, source, operator, input device, counts). Images are stored `(N, H, W, 3)` uint8 in chunks of 32 frames with Blosc/zstd (bit-shuffle); everything else in one chunk with Blosc/zstd.
- `panda_il/data/recorder.py`: `EpisodeRecorder` logs every stream at its own rate with simulation time, wall time and physics substep: `proprio` at 100 Hz from a kinematics pass, `cam_<name>` on each camera's clock (capture and arrival substeps), `action` at the input rate (`log_command`), `obs` and `priv` at every control tick, `init` at reset; `finish()` runs the sync and writes, `finish(discard=...)` drops the episode and counts it.
- `panda_il/data/sync.py`: alignment onto the control ticks: proprio linearly interpolated (quaternions normalised-lerp), cube pose from the privileged stream, cameras by most recent *arrived* frame (stored as an index into the raw frames, images are not duplicated), actions zero-order held; per-stream alignment errors (max and mean, in substeps and seconds).
- `panda_il/data/validate.py`: schema, required attributes/streams/fields, strictly increasing substeps and simulation time, monotonic wall time, gaps > 1.5 nominal periods as dropped frames, NaN/Inf, action bounds, image dtype/shape, source and operator consistency, held-out proximity warning (5 mm and 5 degrees), and the consistency checks: a fresh sync must equal the stored synced arrays, the synced proprio/state must equal the logged observations, the zero-order-held commands must equal what the environment executed, the synced frame choice must equal the frame the environment delivered, and the success flag must match the final streak. CLI `python -m panda_il.data.validate --dataset NAME`.
- `panda_il/data/replay.py`: resets with the logged seed and initial condition, replays the synced actions and compares the privileged simulator state at every tick bit for bit; reports the first divergence, the largest difference, and whether the success flag and final cube pose match. CLI.
- `panda_il/data/render.py`: episode to MP4 (and GIF): the frames the policy saw plus a third-person view re-rendered from the logged simulator state. CLI.
- Environment hooks: `CameraSet.capture_listeners`, exact kinematics before each observation, cube pose and executed action in `info`.
- Tests: `tests/synthetic.py` builds episodes from closed-form functions of the substep with known offsets; `test_sync.py` (9), `test_schema.py` (4), `test_validate.py` (13) run in CI; `test_logger.py` (6) records against the real environment with rendering and is local-only.

## Exit criteria

| Criterion | Result |
|---|---|
| pytest incl. synthetic timing-offset cases | all pass; see the test list below |
| one environment-recorded episode validated | the recorder's own tests record two 30-step episodes plus a discarded one; validator: 0 errors, 0 warnings; replay: both exact |

## Synthetic timing cases (`tests/test_sync.py`)

- Samples exactly at ticks reproduce the ground truth to 1e-12.
- Proprio sampled at substeps 2, 7, 12, ... (2-3 substeps off every tick): interpolation error below the linear-interpolation bound h²/8·max|f''|, reported alignment error exactly 2 substeps (4 ms), quaternions stay unit length.
- Cameras capturing 10 substeps before each tick and arriving 8 later: frame k delivered at tick k with age 10 substeps.
- Latency 12 instead of 8 (arrival 2 substeps after the tick): the previous frame is delivered, ages 25 then 35 substeps.
- Arrival exactly at the tick counts as arrived.
- A dropped camera frame holds the previous one (age 35) and the stream continues.
- Irregular command times (substeps 0, 3, 30, 49, 50, 77 for four steps) are zero-order held to commands 0, 1, 4, 4 with a 25-substep hold reported.
- A step with no command before it raises.

## Validator cases (`tests/test_validate.py`)

A valid synthetic episode passes with no issues. Each corruption is caught with the expected message: NaN in a raw stream, a dropped camera frame (gap), non-monotonic substeps, an action outside [-1, 1], a source mismatch, a tampered synced array, an observation that disagrees with the raw streams, an executed action that disagrees with the commands, a missing stream and a wrong schema version, a success flag that disagrees with the final streak; an initial condition 1 mm from an eval-set pose warns, one 5 cm away does not; the dataset-level report counts episodes, successes, lengths and the maximum alignment error, and flags a corrupted episode.

## Recording against the real environment (`tests/test_logger.py`, local)

For an episode of n control steps: `proprio` has 5n + 1 samples (every 5th substep), `obs` and `priv` n + 1, `action` n, each camera n + 1 frames (reset plus one per tick). Alignment errors: cameras 20 ms (by design), proprio, action and priv 0. The synced frame indices match the frames the environment delivered. Dataset counts after two kept and one discarded episode: `{"episodes": 2, "successes": 0, "discarded": 1}`. Validator: valid. Replay: both episodes bit-for-bit, same outcome. Rendering produces 384 x 776 composite frames.

Smoke run before the tests (two 40-step random-action episodes): store 1.35 MB, 280 files (zarr v3 writes one file per chunk; a 220-episode dataset will be on the order of 30k files, which is why it lives outside OneDrive).

## What failed first and how it was fixed

- The record returned by `finish()` lacked its episode id (it was only stamped on the copy written to the store); the store now stamps the record itself, and `schema_version` is stamped at `finish()` so an in-memory record validates like a stored one.
- The offset-proprio test's synthetic stream stopped 3 substeps before the last tick, so the final value was an edge clamp, not an interpolation, and the error looked 200x too large. The generator now runs past the last tick, as the real recorder does (it always logs a sample at the final tick).
- The first push of this milestone failed CI with `No module named 'panda_il.data'`: the `.gitignore` pattern `data/` (meant for the heavy-artifact folder) also matched the package directory `panda_il/data/`, so git never tracked it, and because ruff honours `.gitignore` the files were never linted locally either. The patterns are now anchored to the repository root (`/data/`), the files are tracked, and ruff's first-party packages are declared explicitly so Windows and Linux sort imports the same way. Three CI runs failed before the fourth passed; all four are in the Actions history.
