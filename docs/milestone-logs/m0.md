# Milestone 0: bootstrap

Date: 2026-10-31. Machine: Windows 11 Home 26200, Intel Core Ultra 7 258V, Intel Arc 140V iGPU, 32 GB RAM.

## What was built

- Repository and package skeleton (`panda_il/` with one subpackage per stage), `pyproject.toml` with the torch backend selected by dependency groups (`xpu` default, `cpu` for CI), `uv.lock`.
- `panda_il/paths.py`: DATA_ROOT resolution (CLI > `PANDA_IL_DATA_ROOT` > `C:\robodata\panda-pick-place-il`).
- `panda_il/device.py`, `panda_il/device_checks.py`, `scripts/check_xpu.py`: the XPU trust logic. The XPU is only handed out when a recorded self-check passed with the installed torch and driver.
- `scripts/bench_device.py`: training-step and inference timings for the model shapes of this project.
- `scripts/fetch_assets.py`: vendors the Menagerie Panda (74 files, Apache-2.0) into `assets/franka_emika_panda/` with `PROVENANCE.md`.
- Pulled forward from M5 because the benchmark needs them: `policies/diffusion/unet1d.py` (Chi et al.'s ConditionalUnet1D) and `policies/encoders.py` (ResNet18-GroupNorm + SpatialSoftmax encoder, crop helper).
- Tests (`tests/`), ruff configuration, GitHub Actions CI (Linux, CPU torch, lint + tests), README, DESIGN.md, RESULTS.md.
- The isolated LeRobot environment `tools/lerobot_env/` (torch 2.11.0+xpu, lerobot 0.6.1, our package as a path dependency).

## XPU self-check on the installed driver (32.0.101.8626)

```
$ uv run python scripts/check_xpu.py

  indexing   FAIL  (6.9 s)
             mask_2061: {'cpu': 1023, 'nonzero': 506, 'index': 506}
             mask_5000: {'cpu': 2507, 'nonzero': 1998, 'index': 1998}
             mask_100000: {'cpu': 50059, 'nonzero': 22470, 'index': 22470}
             mask_1000000: {'cpu': 500608, 'nonzero': 31551, 'index': 31551}
  conv       pass  (12.8 s)
  optimizer  pass  (13.2 s)

verdict: NOT TRUSTED - failed checks: indexing; driver below floor
record: C:\robodata\panda-pick-place-il\xpu_check.json
```

This is the failure the research pass predicted for torch 2.15 on this driver:
`torch.nonzero` and boolean indexing on the XPU return roughly half (and for
large masks a small fraction) of the true count, with no error raised. Every
convolution, GroupNorm and optimizer check passed, which is exactly why a
targeted self-check is needed rather than trusting `torch.xpu.is_available()`.
`panda_il.device.resolve_device("auto")` therefore returns the CPU, and
`resolve_device("xpu")` raises, until the driver is updated to 32.0.101.9150
and the check is re-run. **Exit criterion "self-check passes on the new
driver" is open until then.**

## Device benchmark

`uv run python scripts/bench_device.py --force-xpu --iters 10 --warmup 2`, on a
quiet machine, torch 2.15.0+xpu, 8 CPU threads. `--force-xpu` was needed because
the self-check had not passed; the XPU column is therefore measured on the
untrusted driver 32.0.101.8626 and is re-measured after the driver update
(timings, not correctness, are what matter here). Model sizes: small UNet
(dsed 128, dims 128/256/512) 16.7 M parameters, paper UNet (dsed 256, dims
256/512/1024) 66.1 M, ResNet18 encoder 11.2 M. Raw JSON:
`DATA_ROOT/bench/bench_cpu_20261031_020339.json` and `bench_xpu_20261031_020510.json`.

| benchmark (ms per iteration) | CPU | XPU fp32 | XPU bf16 autocast |
|---|---:|---:|---:|
| MLP-BC 3x512, batch 256, train step | 15.0 | 2.7 | |
| ResNet18 84x84, batch 64, train step | 933.5 | 100.8 | 50.8 |
| UNet small, batch 256, train step (state DP) | 1311.8 | 98.2 | 91.5 |
| UNet paper, batch 256, train step | 5105.6 | 488.4 | |
| Image DP full step, batch 64 (2 cameras x 2 obs steps + small UNet) | 4046.0 | 590.7 | 261.3 |
| UNet small, 10 denoising steps, batch 1 (inference) | 187.7 | 177.7 | |
| UNet paper, 10 denoising steps, batch 1 (inference) | 225.0 | 221.2 | |
| ResNet18, 4 images (inference) | 28.5 | 13.8 | |

What this changes in the plan (DESIGN.md section 7 updated accordingly):

- Training the image policies on the CPU is out (4 s per step, 22 h per 20k-step run); on the iGPU with bf16 autocast it is 1.5 h per run, half the planning estimate.
- A state-based Diffusion Policy run (small UNet, 20k steps at batch 256) takes about 33 min on the iGPU.
- Single-sample inference is launch-overhead bound: ten denoising steps cost ~180 ms on either device. Evaluation will therefore run several episodes in lockstep and batch the policy calls (batch 8 costs about the same as batch 1), which is noted as a milestone 5 design point rather than a budget line.

## LeRobot environment

```
$ cd tools/lerobot_env && uv sync
torch 2.11.0+xpu torchvision 0.26.0+xpu xpu: True
lerobot 0.6.1 numpy 2.2.6 diffusers 0.39.0 av 15.1.0 torchcodec 0.11.1 panda_il 0.1.0
```

Our package imports inside the LeRobot environment, so the export cross-check
and the LeRobot rollout in our environment can share one interpreter.
`LeRobotDataset` and `DiffusionConfig` import, and the config's defaults are the
drifted ones the research pass warned about (horizon 64, n_action_steps 32,
`use_group_norm=False`, ImageNet-pretrained ResNet18, down_dims 512/1024/2048),
so the cross-check must pass the paper's values explicitly. As expected on
Windows, `torchcodec` cannot load its DLLs without FFmpeg shared libraries
(`lerobot-info` prints that traceback); LeRobot 0.6.1 falls back to PyAV, and
every dataset call in milestone 4 passes `video_backend="pyav"`.

## What failed first and how it was fixed

- The editable install failed because `README.md` did not exist yet (hatchling validates the readme field); written before re-running `uv sync`.
- Selecting the torch backend through extras made `uv run` drop the XPU build; moved to dependency groups with `default-groups`.
- ruff classified `panda_il` as third-party because `[tool.ruff] src` pointed at the package directory instead of the project root; fixed, imports re-sorted.
